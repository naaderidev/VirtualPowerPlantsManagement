# گزارش اجرای فاز پنج: قیمت‌گذاری، قرائت، تسویه و صورتحساب

## هدف و دامنه

این فاز زنجیره مالی نسخه اول را مطابق PRD پیاده می‌کند:

`PricingPlan/Index -> Accepted MeterReading -> Versioned Settlement -> Review/Confirmation -> Invoice`

اعتراض مشتری و محاسبه اصلاحی نیز به صورت نسخه جدید تسویه اجرا می‌شود و نسخه قبلی تغییر نمی‌کند.

## موارد پیاده‌سازی‌شده

### موتور قیمت‌گذاری

- محاسبات داخلی با `decimal.js` و گردکردن `ROUND_HALF_UP` انجام می‌شود.
- مدل‌های ثابت، شاخص بازار، ترکیبی و کف/سقف پشتیبانی می‌شوند.
- کف و سقف قبل از ضرب انرژی، روی قیمت واحد اعمال می‌شوند.
- شاخص بازار دیگر از payload محاسبه پذیرفته نمی‌شود و باید با دوره، منبع، timezone و زمان مشاهده در دیتابیس ثبت شده باشد.
- نبود شاخص معتبر محاسبه را متوقف می‌کند و fallback صفر حذف شده است.
- نرخ‌نامه گردش `DRAFT -> REVIEW -> APPROVED -> ACTIVE -> DEPRECATED` و API ساخت نسخه جدید دارد.

### قرائت و تسویه

- قرائت جدید همیشه با وضعیت `RAW` و بدون انرژی پذیرفته‌شده ثبت می‌شود.
- پذیرش فقط پس از `VALIDATED` و توسط نقش فنی مجاز است؛ قرائت نهایی یا استفاده‌شده در تسویه قابل بازنویسی/حذف نیست.
- تسویه فقط از قرائت‌های `ACCEPTED` غیرهم‌پوشان، قرارداد فعال، دارایی متصل، schedule معتبر و نرخ‌نامه فعال ساخته می‌شود.
- مالیات و کسورات hard-coded حذف و از تنظیم مالی تاریخ‌اثر خوانده می‌شوند.
- هر تسویه snapshot ورودی‌های مالی، نسخه نرخ‌نامه، شاخص، تنظیم مالی، فرمول، روش گردکردن و قرائت‌های مصرف‌شده را نگه می‌دارد.
- ساخت تسویه و اتصال قرائت‌ها در یک transaction انجام می‌شود؛ retry همان قرارداد/دارایی/دوره آخرین نسخه را برمی‌گرداند.

### تأیید، اعتراض و اصلاح

- تأیید مالی مرحله‌ای است: `CALCULATED -> UNDER_REVIEW -> CONFIRMED`.
- اعتراض مشتری به دلیل و مهلت قرارداد وابسته است و صورتحساب ناسازگار را لغو می‌کند.
- اصلاح تنها روی تسویه `DISPUTED` انجام می‌شود، دلیل اصلاح اجباری است و نتیجه در نسخه جدید با `supersedesId` ثبت می‌شود.
- نسخه و snapshot قبلی بدون تغییر باقی می‌مانند.

### صورتحساب و ممیزی

- صورتحساب فقط از تسویه `CONFIRMED` صادر می‌شود.
- سررسید از schedule، سپس قرارداد و در نهایت پیش‌فرض ۳۰ روز محاسبه می‌شود.
- صدور صورتحساب و تغییر وضعیت تسویه به `INVOICED` اتمیک و تکرار صدور idempotent است.
- تغییرات نرخ‌نامه، شاخص، تنظیم مالی، تسویه، اصلاح و صورتحساب با actor و correlation ID ممیزی می‌شوند.

## محدودیت‌ها و تصمیم‌های باز

- `D-006`: محاسبه داخلی Decimal است، اما تبدیل همه ستون‌های مالی قدیمی از `Float` تا تصویب scale دقیق انجام نشده است.
- `D-007`، `D-008`، `D-010`، `D-011`، `D-012` و `D-014`: رفتار پیشنهادی پیاده شده ولی برای production نیازمند تصویب رسمی مالی/حقوقی است.
- `D-009`: ساختار ثبت شاخص کامل است، اما نام منبع رسمی و سیاست میانگین‌گیری باید توسط مالی/بازرگانی تصویب شود.
- `D-013`: PDF رسمی صورتحساب تا تعیین هویت حقوقی صادرکننده، اطلاعات بانکی و الگوی شماره‌گذاری آماده انتشار نیست.
- lint کل مخزن ۱۲۰ خطای قدیمی در UI گزارش می‌کند؛ فایل‌های فاز پنج خطای lint ندارند و رفع بدهی عمومی UI در این فاز انجام نشده است.

## وضعیت خروج فاز

هسته عملیاتی فاز پنج برای ادامه توسعه و تست staging آماده است. انتشار مالی واقعی و PDF رسمی تا بسته‌شدن تصمیم‌های `D-006`، `D-009` و `D-013` مجاز نیست.
