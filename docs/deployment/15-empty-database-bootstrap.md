# راه‌اندازی دیتابیس خالی و کاربران تست

## نتیجه

- migration فعال پروژه یک baseline کامل است و روی دیتابیس کاملاً خالی اجرا می‌شود.
- migrationهای افزایشی قبلی برای ردیابی تاریخی در `migrations-legacy-20260913` نگهداری شده‌اند و توسط Prisma اجرا نمی‌شوند.
- seed فقط هشت حساب کاربری، دقیقاً یک حساب برای هر `UserRole`، ایجاد یا به‌روزرسانی می‌کند.
- هیچ Party، رابطه نمایندگی، درخواست، دارایی، پیشنهاد، قرارداد یا داده مالی در seed ساخته نمی‌شود.
- مشتری در نخستین ورود، Party خود را از مسیر onboarding می‌سازد؛ اتصال User و Party در یک transaction ثبت و audit می‌شود.
- Party سیستمی خریدار برقتو تنها هنگام نخستین ایجاد قرارداد و به‌صورت idempotent ساخته می‌شود.

## مرز محیط production

طبق تصمیم امنیتی فاز یک و پروفایل استقرار، seed کاربران آزمایشی در `NODE_ENV=production` همچنان ممنوع است. رمز در کد، migration یا artifact ذخیره نشده و فقط از `ADMIN_SEED_PASSWORD` و `SEED_PASSWORD` خوانده می‌شود. مقدار محلی در فایل git-ignored `.env` قرار می‌گیرد؛ محیط production باید فرایند امن و جداگانه‌ای برای bootstrap مدیر واقعی داشته باشد.

## اجرای محلی

```powershell
npm run db:reset -- --force --skip-generate
```

پس از اجرا باید شمارش User برابر ۸ و شمارش تمام entityهای دامنه صفر باشد. نقش‌های seedشده عبارت‌اند از:

- `ADMIN`
- `STAFF_SUPPLY`
- `STAFF_TECHNICAL`
- `STAFF_LEGAL`
- `STAFF_FINANCIAL`
- `MANAGER`
- `CUSTOMER`
- `CUSTOMER_REPRESENTATIVE`

## مسیر آزمون دستی

1. با حساب `CUSTOMER` وارد شوید و onboarding طرف تجاری را تکمیل کنید.
2. درخواست کوتاه فروش برق را ثبت کنید.
3. با حساب `ADMIN` یا `STAFF_SUPPLY` بررسی اولیه را شروع و تأیید کنید.
4. مشتری اطلاعات کامل نیروگاه، اندازه‌گیری و پیش‌بینی تولید را ثبت کند.
5. تیم داخلی بررسی مالکیت، پیشنهاد، پذیرش پیشنهاد و پیکربندی سه‌لایه قرارداد را انجام دهد.
6. پس از امضای طرفین و رسیدن تاریخ مؤثر، قرارداد فعال شود.
7. قرائت معتبر، تسویه تأییدشده، صورتحساب و تخصیص پرداخت به‌ترتیب آزموده شوند.

خالص‌سازی خارج از این مسیر پایه و تا زمان فعال‌سازی feature flag و وجود گروه معتبر غیرفعال است.
