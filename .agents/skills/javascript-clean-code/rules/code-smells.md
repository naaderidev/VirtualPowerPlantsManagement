# Code Smells

Investigate:
- generic names
- long functions
- long parameter lists
- deep nesting
- god classes/modules
- duplicated logic
- circular dependencies
- hidden global state
- swallowed errors
- excessive mocking
- flaky tests
- speculative abstractions
- boolean flags with branching behavior
- mixed transport/domain/persistence responsibilities
- helpers that hide important side effects
- premature performance optimizations

A smell is a signal for investigation, not automatic proof that code is wrong.
